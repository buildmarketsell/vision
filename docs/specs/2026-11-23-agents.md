# Agents (after Bupsy)

Dan, 2026-11-23: "create a new thing inside VISION, make it Agents… as close as possible to Bupsy… not bloated, fast and token efficient." Bupsy (bupsy.si, Xocket Labs) is a SwiftUI app; its design is copied, its code is not (different language). Words in `GLOSSARY.md`.

## What Dan sees
- **Agents** in the left menu. The page has Bupsy's own column on the left (Waiting on you, Routines, Pinned, then agents by folder, New agent) and the chosen agent's chat on the right.
- Chat looks like Bupsy: breadcrumb `Agents | Name | Chat` and a Details button on top; date line; Dan's messages as grey bubbles on the right; the agent's replies with its face, name and time; tool steps as quiet one-liners; approvals as a card with a pink lip (Allow / Deny); a thinking line (face, current step, seconds) while it works; composer "Message <name>" with a pink send button.
- Details: face (shape + colour), name, role, job, folder, model, trust level, pinned, Fresh chat, Delete.
- New agent: a sheet with a face preview, name, job and folder.
- Waiting on you: every open approval and question from all agents, answerable in place. Count badge in the column. A Mac notification when an agent needs Dan and VISION isn't in front.
- Routines: list and create (agent, what to say, daily / weekdays / weekly at a time), pause, run now, last run.
- Colours: Bupsy's pink for what needs Dan, greys from the VISION theme, so every theme works. Faces from Bupsy's 14-shape gallery in its 8 colours.

## Not built (on purpose)
Groups and @mention handoff, standing goals, voice, other devices, cloud machines, Codex and local models, background helper for routines while VISION is quit.

## Token efficiency
- One process per agent, started on the first message and stopped after 10 idle minutes (no cost while idle; `--resume` continues the same chat).
- The job goes in `--append-system-prompt`, short; the folder's own CLAUDE.md loads as usual.
- Fresh chat: the agent writes a handoff note (one short turn), the chat restarts with only that note.
- Each agent has its own model (default Sonnet for new agents is not forced: Default = Claude Code's choice).

## Modules
- `src/shared/chat/` (moved from the Claude tab): the pure reducer from stream-json events to chat state. Main and renderer both run it, so they always agree.
- `src/main/claude/claudeProcess.ts`: starts one `claude -p` process (chat tabs and agents).
- `src/shared/agents.ts` (pure, unit tested): `Agent`, `normalizeAgents`, trust level → Claude flags, face from name, the agent's mood from its chat state, `agentSystemPrompt`.
- `src/shared/routines.ts` (pure, unit tested): `Routine`, `normalizeRoutines`, `nextRunAt`, `dueRoutines` (missed runs fire once).
- `src/features/agents/main/`: `agentStore.ts` (agents.json, routines.json via `createJsonListStore`), `agentRuns.ts` (process per agent, its chat state, updates to windows, idle stop, fresh chat, notifications), `routineClock.ts` (checks every 30 s).
- `src/features/agents/renderer/`: page, column, thread, details, creator, waiting, routines, face.
